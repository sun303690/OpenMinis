## 一、执行触发 & 结束标准

**触发场景**

1. 成果确认可用，需要正式存入知识库
2. 需要对知识库内容：合并、重命名、清理冗余、修复引用链接

**结束标准（满足才算完工）**

三项全部达标：

1. 三同步完成
2. 全库无死链（按第六节脚本实测，输出 0 条）
3. 收尾自检 6 问全部通过

---

## 二、核心入库判定（最简无矛盾规则）

**核心一句话准则**

- 删除当前文件后，**无法**通过笔记 + 脚本完整复原 → **必须入库保存**
- 删除当前文件后，**可以**通过笔记 + 脚本一键复原 → **不入库**，仅放运行目录 `mounts/mcp`

**✅ 必须入库永久保留**

1. 各类可复用脚本、完整代码、源码、配置文件
2. 实测有效环境配置、环境搭建方案、环境踩坑结论
3. 方法论、操作流程、通用模板、万能句式、解题思路
4. 关键结论、实测数据、验证结果、避坑经验
5. 长期有效索引目录、结构化笔记、归档规范
6. 固定流程、落地方案、定型教程、长期资源清单

**❌ 绝不入库、必须清理（临时 / 中间产物）**

1. 原始安装包、原始素材、缓存文件
2. 调试 dump 文件、运行中间数据、临时输出内容
3. 多轮对话副本、重复生成物、草稿残稿
4. 临时日志、调试缓存、workspace 垃圾文件
5. 一次性临时产物、过期测试文件
6. 未通过验证的成品（APK、打包脚本成品）

**边界补充（易混项）**

| # | 情况 | 处置 |
|---|---|---|
| 1 | 代码 / 源码未测 | **收**，标注「未验证」；**成品**未验证则不收 |
| 2 | 脚本只跑一次但有复现价值 | **收**，用后补验证 |
| 3 | 脚本只针对单包、不可泛化 | **不收**，结论进笔记 |
| 4 | 大段 smali 补丁 | **只收**改动类 / 方法片段 |
| 5 | 接口样例含真实凭据 | **脱敏后收** |
| 6 | 同问题两方案 | **都收** + 记被推翻的 |

## 三、标准笔记八段结构（缺则留空，绝不编造）

1. **定位与边界**：适用场景、不适用场景
2. **版本 / 演进记录**：迭代更新、修改记录
3. **决策依据**：最终选择 + 被推翻的备选方案（最有价值）
4. **关键实现**：核心操作、核心代码、核心步骤
5. **踩坑记录**：报错、问题、原因、解决方案
6. **复现链路**：从零完整复现步骤
7. **待办状态**：未完成、待优化、待验证项
8. **可复用资源**：脚本 / 模板 / 配置 / 代码

> **硬性要求**：所有环境结论必须当轮实测，禁止照搬旧笔记、旧结论。

---

## 四、三同步规则（少一项必出死链，强制全同步）

所有入库、修改、移动、删除操作后，必须完成以下同步：

1. **子库索引同步**：对应文件夹 README / 索引文件，登记「篇名 + 主题 + 核心结论」
2. **总库索引同步**：`notes/_索引.md` 总清单实时更新，篇数对齐
3. **镜像目录同步**：`shared/notes/A/B.md` → `mounts/mcp/知识库/A/B.md`
   （去掉 `notes` 前缀，其余路径完全一致），用 `diff -rq` 验证无差异
4. **skills / tools 自引用同步**：全局检索引用 → 逐条修复 → 同步镜像 → 逐个验证文件存在

---

## 五、修改 / 清理 前置检查规则

1. 文件移动、改名、删除前：全局检索所有引用（notes + skills + tools 自引用），逐条修复链接 → 同步镜像 → 验证文件有效
2. 批量清理：删除 ≥10 个文件 / ≥50MB 资源，先归档到清理备份文件夹，再执行删除
3. 内容合并：同一项目多篇草稿，统一合并为一篇定稿
4. **旧稿删除判定**：新稿八段中 ①③⑥⑦⑧ 均不劣于旧稿，且新增内容可追溯至验证记录，才可删旧稿并留存删除证据；否则两篇并存，索引标「并存」
5. 公共资源保护：`shared/` 公共目录内容，非本轮确认内容，禁止随意修改、删除

## 六、死链检测（退出条件必查）

**唯一正确做法**（2026-11-03 实测：353 条链接，死链 0）：

```sh
python3 /var/minis/shared/tools/知识库维护/check_links.py     # 必须输出「死链 0 条」
```

> ❌ **不要用 `rg` 单行命令**（`rg -o '\]\([^)]+\)' notes/ --no-filename | … | [ -e "$p" ] …`）：
> 它会丢掉「链接来自哪个文件」，而笔记里的链接是**相对文件所在目录**的，
> 按当前目录判断会把正常链接全报成死链 —— **实测误报 89 条**。原命令已废弃，仅作反面记录。

## 七、收尾自检 6 问（完工必查）

1. 核心产物是否放入 `mounts/mcp`，设备可正常查看？
2. 是否**误写**入沙箱 `/storage`？落进即迁回（禁止 `/storage/**`、`/sdcard/**`、`/data/local/tmp`）
3. 所有引用链接、镜像目录是否完全同步一致？
4. 临时缓存、workspace 垃圾是否全部清理？
5. 新笔记是否成功录入全局索引清单？
6. 本轮新增 / 改动笔记的交叉引用是否全部指向存在的文件？（按第六节脚本实测）

## 八、最终交付固定内容

每次维护完成，固定输出 5 项：

1. 笔记完整路径
2. 索引变更记录
3. 镜像同步状态
4. 合并 / 删除清单
5. 死链数量（**强制为 0**）
