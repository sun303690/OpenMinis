**触发**：拿到一个已存在的 APK，要改它的行为（去广告/解锁/改逻辑/修 bug/去限制）。
**退出**：需要写新工程 → 开发版；遇到壳 → 脱壳版；只出报告不改 → 分析版。

---

## 1. 流程（七步，不许跳）

`读笔记 → 侦察 → 权威方判定 → 定位最小改动点 → 改 → 验证 → 交付`

（标题曾写"六步"是笔误：读笔记、侦察、权威方判定、定位、改、验证、交付实际是 7 项，2026-11-03 已改正。）

侦察阶段固定产出：包名 / versionCode / 加固与否 / 签名 / dex 数与类数 / 关键 SDK。
没出这 6 项之前不要打开 smali。

## 2. 强校验先判权威方（本卡最重要）

**客户端可改**：本地开关、`isVip` 判断、`getHasRight()`、广告开关、UI 拦截、到期时间显示。

**服务端限制，客户端改不动**：服务端签名验签、token 有效期/权限位、服务端时间戳/服务端 nonce、
设备指纹与设备数限制、风控与频控、内容按权限下发（只下发试看片段）。

**易误判的一条 —— 证书绑定（pinning）**：它跑在**客户端**，技术上可改（去 pinner / Hook TrustManager），
但它只挡**抓包**，不挡功能。别把它列进「不可绕的服务端强校验」，也别指望改掉它就能解锁——它和授权无关。

**判法**：先问一句——「这个限制的**决定权**在谁的返回里？」
- 决定权在本地字段 → 改本地。
- 决定权在服务端返回（空 url、试看时长、`hasRight=false`、403）→ **改本地一律无效**，别浪费轮次。

**无法绕过时，按这个模板给结论，不许伪造成功**：

```
类型：服务端 token 校验 / 证书绑定 / 设备指纹 / 风控（选一）
证据：E3 请求响应原文 或 E4 自构造请求返回（贴关键字段）
原因：决定权在服务端，客户端只做呈现
替代方案候选（实际最多选 2 种）：
  A Hook 取参 → 拿已授权的真实参数复用
  B 重放 → 用真机真号的真请求，只改需求侧参数
  C 本地伪造响应 → 只对 UI 生效，明确告知「非真解锁」
  D 离线降级 → 断网用缓存/本地资源
  E 真机真号 → 用户自己账号
结论：候选方案最多验证 2 种；仍不可行时直接写「不可行」，并给出可行边界（如：能看到的范围 X）。
```

**禁止**：把 UI 上显示出 VIP 当成「破解成功」；把 demo 文件当成完整资源交付。
参考 skill：`signature-bypass`、`reverse-patch-techniques`。

## 3. 改动纪律

- **最小改点**：只改决定分支的那 1~2 个方法，不重构、不美化、不动无关类。
- 优先顺序：资源/清单改（最安全）→ smali 方法体改 → 加类（最后）。
- Hook 能解决的不改 smali（可回滚、可复测）。
- 原地等长替换要求新指令 u2 数 ≤ 原 `insns_size`；不够就重写方法体而不是硬塞。
- 改完必须用 MT MCP 重打包/签名后**真机装一次**，模拟器不算验证；`d8` 只用于 Java/Kotlin 编译产物，不是 APK 签名工具。
- MT MCP 当前改 DEX 走 `mt_apk_read_text → mt_apk_edit_text → mt_apk_build(sign=true)`；
  `mt_apk_patch_bytes` 对 DEX 可能返回 `PATCH_UNSUPPORTED_ENTRY`，不要把二进制 patch 当默认路线。
- 临时 MT 工作区编辑不跨会话持久；重开工作区后必须重放补丁，再 build。

## 4. 交付

| 项 | 要求 |
|---|---|
| 命名 | `<原名>_v<n>_<yyyyMMdd-HHmm>.apk`，旧版不覆盖 |
| 版本标识 | **必须**改 `versionName` 打后缀（如 `3.2.16-pat1`）；`versionCode` 同步 +1（重签后签名不同，覆盖安装仍需先卸载，+1 只为标记迭代与防降级报错） |
| 签名 | 只用 MT MCP（V1+V2+V3），沙箱内无其他可行途径 |
| 自检 | 签名校验通过 + 启动不崩 + 目标功能实测 + 原功能抽查 2 处以外未被误伤 |
| 报告 | 首行目标锚点；修改清单表（dex / 类 / 方法 / 改动）；证据等级；验证点（用户该点什么能看到效果） |

## 5. 必查清单

- [ ] 有没有加固（`libjiagu`/`libshella`/`StubApp`/`assets/*.dat`）
- [ ] 有没有签名校验（`getPackageInfo` + `signatures`、`MessageDigest`、native `JNI_OnLoad`）
- [ ] 有没有完整性校验（dex 自校验、资源 hash、二次解压）
- [ ] 限制字段来自哪个接口（抓一次，别猜）
- [ ] 改完的 dex 是否 ART 接受（装不上先看 `pm install` 返回码）
