**触发**：判断限制/数据来自客户端还是服务端；复刻接口；还原加密与签名。
**退出**：定性完成 → 逆向版；协议可复用 → 项目方案/抓取；证据不足 → 明说缺哪一级。

## 1. 唯一目标：判权威方

抓包不是攒包，是回答一句：**这个字段谁算的、谁验的。**
单次完整请求 + 响应里，必须标出：必填参数、可疑签名参数、token 来源、服务端判定字段
（`hasRight`/`vip`/`expire`/`url`/`demoDuration`/`videoSegments`）。

## 2. 顺序与当前可用手段

`定目标请求 → 选通道 → 解密/取参 → 判签名 → 重放验证`

### 2.1 通道选择（按可靠性排序）

| 通道 | 适用 | 当前条件 |
|---|---|---|
| **Hook 数据层取参**（LSPosed） | ExoPlayer、Flutter、自写网络栈等不走系统代理的 | ✅ 已装 LSPosed；小猿 AI 视频流即此法一击定性 |
| 设备端抓包 App | 普通 HTTP/HTTPS | 需设备侧安装（历史用过 Reqable 抓包数据） |
| 电脑/沙箱代理 | 走系统代理的 App | 需同一局域网 + 代理可达 |
| 直接重放接口 | 已知 URL/参数 | ✅ 沙箱 `curl`/Python 均可 |

**优先级**：Hook 取参 > 设备抓包 > 代理抓包 > 盲猜接口。
不走代理就换通道，不要反复调代理设置。

### 2.2 装系统 CA（要在真机做，且属于「写系统分区」——按 _BASE B3 先确认）

**条件具备但流程未实测**：真机有 Magisk root、真机侧 `/system/etc/security/cacerts` 现有 150 个证书
（沙箱内不存在 `/system/etc`，是两套文件系统）。**"目录存在"≠"用户证书已装"**，本机还没有跑通过完整的装证书流程。
做法：把证书按 `<hash>.0` 放入 Magisk 模块并 bind mount 到系统证书目录，重启后生效；
不要直接在沙箱 rootfs 里改 `/system`（改了也不影响真机）。
首次使用请先用一个已知 HTTPS 站点验证证书是否真的生效，再抓目标 App。

必须知道的两条：
- `targetSdk ≥ 24` 的 App 默认**不信任用户装 CA**，必须走系统 CA。
- Android 14+ 对用户 CA 限制更严；系统 CA 仍是通用解。

## 3. 判强校验（与逆向版同一条红线）

**不可单方绕过**：服务端签名、服务端时间戳/nonce、token 权限位、设备指纹、风控频控。
**属客户端、可绕**：证书绑定 pinning（去 pinner / Hook TrustManager）——只解决「抓不到」，不解决「没权限」。

下游结论模板与替代方案见 `人格_逆向版.md` 第 2 节。

**重放纪律**：只用自有账号、自有设备、低频次；不刷接口、不批量拉取、不绕过计费。

## 4. 判签名参数是否值为空

小猿 AI 新版 `video-replay-v3` 的 `sign=` **实测为空**，说明它不需要签名。
先确认「参数存在 ≠ 参数有效」，别花时间逆向一个不参与校验的字段。

## 5. 交付

- 接口清单表：URL / 方法 / 必要头 / 参数 / 响应关键字段 / 判定字段 / 证据等级。
- 签名算法：给完整推导链与验证样例；给不出就写「未还原」，不猜。
- 脚本只作辅助；不把他人密钥、cookie、账号、真实身份写进笔记。

必读：`hybrid-h5-reverse`、`protocol-crypto-analysis`、`flutter-reverse`、`performing-dynamic-analysis-of-android-app`。
